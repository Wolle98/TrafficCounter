# TrafficCounter – notes for Claude

- Plan and status: `docs/roadmap.md` (update status markers when finishing tasks). Architecture: `docs/architecture.md`.
- Session hand-off: `docs/HANDOFF.md` in the private repo (German). Keep it current: with every new version and whenever operation changes (camera, model, configuration on the counting machine, databases, schedules, running work), update its sections "Betrieb", "Abläufe" and "Laufende Arbeit" and the date at the top, then commit and push the private repo.
- Decisions: `docs/adr/` (MADR). New decision → new ADR from `0000-template.md`, next free number, add to `docs/adr/README.md`. Never rewrite an accepted ADR; supersede it.
- Language: everything in this repo is English – docs, ADRs, code, identifiers, comments, commit messages, tool help texts (ADR-0036). The analysis app UI is multilingual (ADR-0037): every UI text goes into `src/TrafficCounter.App/Resources/Strings.resx` (English) and each `Strings.<lang>.resx`.
- **Working repo, published as snapshots (ADR-0045).** This is `Wolle98/TrafficCounterWork` (private); every version is published to the public `Wolle98/TrafficCounter` with `tools/publish/Publish-PublicSnapshot.ps1`, which stops at patterns from the private `config/publish-denylist.txt`. Treat everything here as public anyway: never add images, videos, site-specific config, real DB data, model weights or secrets here. Those belong in the private repo `D:\Code\TrafficCounterPrivate` (located via env `TRAFFICCOUNTER_PRIVATE` / `TRAFFICCOUNTER_CONFIG`). Secrets go to `dotnet user-secrets` / env vars, never into either repo.
- Issues (ADR-0022): only larger problems (data-affecting bugs, design flaws, stability). Propose first, create after the user agrees (`gh`; if not on PATH: `C:\Program Files\GitHub CLI\gh.exe`). Before creating, classify and state the target: anything that could hint at location, persons, vehicles or refers to private files → issue in `Wolle98/TrafficCounterPrivate`; if in doubt, private. Technical issues go to the public `Wolle98/TrafficCounter`. Public issues, commits, docs and code never mention private issues. Code, docs and the CHANGELOG refer to ADRs, not to issue numbers. A new finding that hints at the site also goes into `publish-denylist.txt`.
- Versions (ADR-0038): one `<Version>` in `Directory.Build.props` for all programs. Before deploying to the counting machine raise it (minor: features or data-relevant changes, patch: fixes), add the changes to `CHANGELOG.md` and tag the commit `v<version>`.
- `TrafficCounter.Core` must stay free of OpenCV/ONNX/EF dependencies.
- Always dispose OpenCvSharp `Mat` objects (`using`) – 24/7 service.
